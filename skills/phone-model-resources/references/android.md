# Android

使用官方 ADB，通过 USB 调试连接。扫描设备，多个设备让用户选择，未授权引导解锁手机并同意调试。先只读查找目标 App 外部资源目录中的 resources.json，车型和版本来自实际文件，不硬编码示例。

先以 tar/二进制管道完整导出选中目录，拒绝路径穿越、符号链接和大小写冲突，验证 ZIP 与 .ab 平台。写入前保存原资源 ZIP、解压文件 SHA256 清单和恢复事务日志。元数据必须对应目标资源，不能将同一包随意写入不同版本目录。

Windows 避免向 adb pull/push 传递中文本地路径。参考实现将文件 Base64 编为 ASCII，通过 `adb shell -T 'base64 -d > <quoted-remote-file>'` 传输，手机端解码，逐文件 MD5 核对原始字节。先验证设备上 base64 命令可用。不要把二进制直接送入未确认二进制模式的 Windows shell 标准输入。错误日志保留预期/实际大小与哈希。

优先写入同级临时目录 `.helper-stage-随机值`，全量验证后换目录。若不能创建同级目录，探测现有目标是否可写，可写才采用本地完整备份加原位写入、校验、失败回滚。两者均拒绝则结束并报告，不能绕过系统权限。不可在校验前删除原资源。断线保留事务日志及备份，再连接同一设备和目录恢复。

写入完成重新打开 App，由用户确认外观，联网冷启动复查。导出包本身不等于原厂状态，可能已是用户定制资源。
