# 手机模型资源

本 Skill 的任务是在用户电脑生成一套可独立运行的本地网页引导程序，完成后交付明确的启动入口。用户打开入口后自动启动后台和网页，后续导出、选包、写入、确认、故障处理与答疑都在网页完成。AI 在生成阶段负责实现和验证；程序后续运行无需 AI 对话或 AI 会话存活。读取本 Skill 的所有执行能力都来自当前 AI 宿主提供的文件、命令、浏览器等工具。不要要求用户安装原桌面助手、下载其 Release 或连接作者服务。本 Skill 自包含的源码参考可用于理解和改写实现，不是必须运行的后台服务。

## 品牌支持与入口

产品定位为通用手机 AssetBundle 资源包与模型获取、写入 Skill；当前已实现适配仅为蔚来（NIO）。通用定位不代表已支持全部品牌或 App。

生成的网页首先要求用户确认目标品牌，再选择 Android/iPhone 与导出/替换。已有用户明确说明品牌时可预选，但仍在任务摘要显示并允许修改。品牌选择在网页完成，无需先返回聊天问答。

只有选择蔚来才能进入现有适配流程。选择其他品牌或不确定时，页面明确显示“目前仅支持蔚来，所选品牌暂未支持”，提供重新选择品牌入口，停止本任务的 App 扫描、代理拦截、资源获取和写入；不能将蔚来的包名、接口或资源路径用于其他品牌，也不能猜测兼容。已运行任务切换品牌先安全结束旧任务，iPhone 提醒关闭手机代理，并清理旧任务状态。

用户在聊天直接询问其他品牌时，立即说明目前暂未支持，提供已生成页面的品牌选择入口；不得宣称支持所有手机 App 或临时自动适配其他品牌。新增品牌适配需要用户另行提出开发需求及真实验证。

品牌显示与技术标识分别处理。页面以品牌名称清楚说明支持范围；代码、日志和 profile 中保留调用真实 App 所需的准确标识，不为泛化产品而改坏协议。不要将手机厂商误认为目标品牌，例如 Motorola 手机上的蔚来 App，目标品牌仍为蔚来。

## 操作设备与小白引导

生成和修改任何操作页面前，读取 [设备明确的逐步引导](references/device-guidance.md)。每一步明确“在电脑上／在 iPhone 上／在安卓手机上操作”、打开什么、做什么、完成标志以及回哪里确认。正常、错误、等待和退出页均适用。设置路径不能省略设备名。依照全链路对照表检查并输出 guidance-audit.json；保持单步简洁，避免堆叠长文案。

## 默认实现路线与时间控制

收到生成或更新程序请求后直接实施，已有授权下不再以“要重做请说一声”结束。安装 Skill 只需核对入口和资源完整性，避免先输出逐文件审计长报告。

默认采用已有 0.2.3 基准的 Python 后端、HTML 手机/桌面向导、mitmproxy 插件和 AndroidBridge。直接复制基准并作局部适配，禁止在缺少具体技术障碍时重新设计共享层、服务层、状态机、ZIP校验和代理协议。不同电脑主要适配运行时、启动器和路径。用户明确要求其他技术栈时才采用其他方案。

已有用户程序优先增量修复，保留可用运行时、证书、备份和状态协议。缺二维码补二维码，缺平台入口补入口，不自动重建整套程序。只有证据表明旧程序无法合理适配时重建，并说明具体障碍。

先做短环境探测，定位可用 Python、mitmdump、ADB、架构和原生成目录。可执行的独立 mitmdump 可以直接作为子进程载入插件，不要求能 import mitmproxy；不得仅因 import 失败重装整个代理运行时。模块导入测试用到的开发依赖不应迫使产品换运行架构。已有兼容局部运行时优先复用，缺少的依赖一次准备，锁定版本并缓存。

以基准 backend/app.py 为服务起点，用一层浏览器页面适配桌面功能。二维码、证书、日志、资源接口已有实现时直接连接。desktop/main.cjs、renderer.js 中的设备选择、首次备份、文件保存、写入确认、返回首页和退出行为映射为网页操作及少量服务路由，不重新实现代理和写入算法。基准程序仍须检查依赖、来源和权限，不能把复制源码当作已通过现场验收。

功能清单定义最终覆盖范围，不代表每次都要逐文件审计、重新编写测试或重跑全部合成组合。未改核心使用现有测试，改动部分跑针对性回归；入口健康、二维码真实解码、手机页、平台切换、人工确认和退出是本次必要检查。真机未接时标 not-tested，不为填满报告无限增加 stub。测试失败先区分产品缺陷和测试桩问题，避免为测试重写稳定核心。

首轮尽快形成可打开页面，再补适配并交付。一次环境准备失败允许有根据地调整一次，持续失败时报告具体障碍和已完成结果。没有实测依据不承诺固定分钟数，不以时间目标删减功能。进度仅报告关键发现、阻碍和可用结果。

## 0.2.3 功能基准

开始生成前读取 [功能与验收契约](references/feature-parity.md) 及 [逐项清单](references/feature-parity.json)。这是交付范围，网页二维码、手机引导、备份、导航、手动确认、持久化与故障恢复均需逐项实现。完整参考材料在 `references/baseline-0.2.3/`，基准文件清单附 SHA256。架构由当前环境决定，功能覆盖按编号验收。不要仅依赖下面的流程摘要生成简化版。

生成后提交逐项 acceptance-report.json 和实测证据，区分已通过、失败及未测试。完成页面和服务可运行检查后才能交付，不能只交付设计稿或功能按钮占位。

## 必须完成的交付契约

本 Skill 被调用后，默认目标是生成、运行并交付可操作的本地网页程序。只有用户明确仅询问原理、要求暂停或限制执行时才缩小范围。聊天中解释了操作流程、给出了地址、展示了静态示意页，都不构成完成。

- 在发送手机证书安装、完全信任、Wi-Fi 代理或 USB 操作指令前，先把对应步骤实现到实际运行的网页中，并验证可访问。用户从网页查看这些步骤并确认完成。
- 网页首页先确认目标品牌，目前仅开放蔚来，再提供 Android 与 iPhone，以及导出与写入两个任务。按选择逐步准备依赖。已实现 Android 后用户说“现在是 iPhone”，应更新或打开网页中的 iPhone 流程，不能退回聊天列步骤、再问用户是否启动。
- 用户通过网页选择设备、平台、资源包、确认备份和写入授权。授权提示按宿主实际规则执行；除宿主确实要求外，不得另设“先在聊天说一声才能启用”的条件。写入备份可由网页自动完成，不能永久灰显。
- 任务参数、手机号平台切换、证书下载、连接检查、下载、写入、手动外观确认、持久化收尾、正常联网验证、重试、保存日志、退出，都必须有实际服务接口和网页操作。若某一能力尚未完成，继续实现并验证，不能将其包装为已完成产品。
- 聊天交付只需说明入口、当前可用状态及真实阻碍，通常一到三句话。手机分步操作、长篇环境报告、常规风险和每步确认放在网页中。用户主动提问可简短答疑，同时继续完善网页。
- 默认只导出用户当前车型的完整资源包。没有用户明确要求时，不扩展为“轻量/标准/完整”等全车型或缓存档位，不扫描和打包无关资源。
- 不把原助手或历史个人环境视为依赖。为当前用户检测环境，所有设备、版本、地址、空间及成功结果来自本次观测。

如果当前宿主无法生成文件、启动本地进程或打开网页，明确列出缺失能力。此时可交付已完成的文件和启动入口，不得擅自把整套流程改成聊天代办并宣称满足本 Skill。

## 进入任务

自动检测电脑系统和架构，读取已有记录。生成程序时提供手机平台、导出或写入、选择文件等网页操作入口，无需先在聊天中收集每次任务参数。只有生成程序所需且环境无法确定的信息才询问用户。只处理用户有相应授权的资源，界面简短说明授权使用要求。模型不上传云端。不要索取账号令牌或完整 VIN。

开始手机写操作前说明会关闭目标 App 并备份现有资源，沿用用户已有授权。不得影响用户未选中的设备。执行能力不足时明确缺少什么，完成能做的准备，不能宣称已操作手机。Skill 本身不能赋予宿主执行权限。

选择平台后读 [Android](references/android.md) 或 [iPhone](references/iphone.md)。创建引导前读 [本地体验与执行约定](references/local-experience.md) 和 [自动启动与验收](references/launch-and-acceptance.md)。按需查阅 `references/baseline-0.2.3/` 中的独立源码参考，理解协议后在用户任务目录生成适合当地环境的实现。不要复用参考中的个人路径、历史资源标识或启动参数作为用户实测结果。

## 工作与交付

1. 为当前系统和架构生成程序及启动入口，提供一个可双击的主入口。Mac 可生成 .app，Windows 可生成启动器 .exe；若采用 .command 或 .cmd，仍须自动完成全部启动步骤并清晰标识入口。用户无需手动打开终端或另开后台。
2. 由入口自动检测、准备局部运行时和依赖。运行时优先随生成结果附带；可按用户允许的网络条件自动从官方来源获取并缓存。首次准备要显示进度、错误和重试，之后复用。运行不得依赖 AI 临时注入的环境变量或开发终端。具体要求见启动参考。
3. 服务健康检查通过后自动打开浏览器到本次会话网页。网页提供完整步骤、常见问题、故障检测、日志导出和退出入口。日常操作不跳回聊天。没有嵌入 AI 也必须能完成全部任务和常见故障恢复。
4. 持久保存会话、平台、目标资源、真实文件哈希、阶段和用户确认。浏览器刷新、关闭后重开、程序重启都能正确恢复或解释中断阶段，不能丢失备份、伪造连接或误显示上一任务成功。
5. 在无 AI 会话帮助的新进程中测试主入口，检查缺依赖、重复双击、端口占用、目录空格/中文、页面刷新、退出和再次启动。按参考完成验收，明确尚未实际测试的平台及真机流程。
6. 交付程序所在目录和主入口名称，用户只需打开入口。获取任务在网页保存 ZIP 与清单，写入任务在网页分别确认外观、持久化收尾和正常联网冷启动。
7. 程序提供“退出程序”，先引导 iPhone 用户关闭手机代理，再结束本次服务及子进程。单纯关闭浏览器标签不能假设已退出后台。提供托盘/菜单栏退出或入口中的停止操作与恢复网页功能，避免后台失联。

## 证据与答疑

不要根据候选顺序、文件名或包内默认值推测当前车辆选配。iPhone 无法取得当前选配时正常导出资源。可选 current_configuration.json 协议见基准 backend/configuration_export.py。

以实际状态回答“是否成功”“为什么卡住”“能否退出”。用户说手机外观已生效时，接受其手动确认，记录来源并推进后续收尾，不能因未观察到完整 ZIP 响应永久禁用按钮。15 秒是建议前台停留时间。当前包、当前会话、阶段、失败状态仍需核对。代理记录仅证明观测到的事件。

本 Skill 的参考流程有历史真机验证，但不同 App、车型、系统和宿主环境仍需现场验证。不得把“任意 AI 可加载文字”承诺为“任意 AI 都能执行本地操作”。
